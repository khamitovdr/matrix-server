# Matrix Server — Self-Hosted Messaging Platform Design

## Overview

A self-hosted messaging server with audio/video calling, deployed to a single VPS via Docker Compose. One `deploy.sh` script handles everything from initial provisioning to ongoing management.

**Target VPS:** Ubuntu 24.04, 4 CPUs, 8 GB RAM, 140 GB SSD
**Domain:** branga.ru

## Stack

| Component | Role |
|---|---|
| Synapse | Matrix homeserver |
| PostgreSQL 16 | Database |
| Element Web | Web client |
| LiveKit | WebRTC SFU for audio/video calls |
| lk-jwt-service | JWT token issuer for Element Call → LiveKit |
| coturn | TURN/STUN relay for NAT traversal |
| Caddy 2 | Reverse proxy, automatic TLS via Let's Encrypt |

## Subdomains

| Subdomain | Routes to |
|---|---|
| `matrix.branga.ru` | Synapse (port 8008) |
| `element.branga.ru` | Element Web (port 80) |
| `livekit.branga.ru` | LiveKit (port 7880) |
| `livekit.branga.ru/jwt` | lk-jwt-service |
| `turn.branga.ru` | coturn |

## Docker Compose Architecture

### Services

All services use `restart: unless-stopped`.

| Service | Image | Exposed Ports | Notes |
|---|---|---|---|
| `caddy` | `caddy:2` | 80, 443 | Reverse proxy, auto TLS |
| `synapse` | `matrixdotorg/synapse:latest` | internal | Matrix homeserver, monolith mode |
| `postgres` | `postgres:16` | internal | Database |
| `element` | `vectorim/element-web:latest` | internal | Static web client |
| `livekit` | `livekit/livekit-server:latest` | 7880, 7881 | WebRTC SFU |
| `livekit-jwt` | `ghcr.io/element-hq/lk-jwt-service` | internal | JWT issuer for calls |
| `coturn` | `coturn/coturn:latest` | 3478/udp, 3478/tcp, 5349/tcp, 49152-49200/udp | TURN/STUN relay |

### Network

Single Docker bridge network (`matrix-net`) connecting all services.

### Volumes

| Volume | Purpose |
|---|---|
| `postgres_data` | PostgreSQL data persistence |
| `synapse_data` | Synapse signing keys, media cache |
| `caddy_data` | TLS certificates |
| `caddy_config` | Caddy auto-config |

### Reboot Resistance

- All containers: `restart: unless-stopped`
- Provision script: `systemctl enable docker`
- Named volumes: data survives container recreation

## Deploy Flow

### Entry point

```bash
./deploy.sh [--provision] [--deploy] [--create-user <username>] [--backup-now] [--restore [timestamp]]
```

### First-time deploy (`./deploy.sh --provision --deploy`)

1. **Validate** — Check `config.yaml` exists, verify required fields
2. **Provision** (over SSH):
   - Update packages, install Docker + Docker Compose plugin
   - `systemctl enable docker`
   - Configure UFW: allow 22, 80, 443, 3478, 5349, 7880, 7881, 49152-49200/udp
   - Create deploy directory (`/opt/matrix-server`)
   - Install MinIO client (`mc`) for S3 operations
   - Set up backup cron job
   - Set up media cleanup cron job
3. **Generate secrets** — Run `generate-secrets.sh` on VPS, creates `.env`
4. **Render configs** — Process `.template` files locally with `config.yaml` values
5. **Copy files** — SCP rendered configs, `docker-compose.yml`, scripts to VPS
6. **Start stack** — `docker compose up -d`
7. **Health check** — Verify Synapse responds on `matrix.branga.ru`

### Subsequent deploys (`./deploy.sh --deploy`)

Steps 4-7 only. Preserves existing `.env`.

## Synapse Configuration

- **Database:** PostgreSQL via `psycopg2`
- **Server name:** `branga.ru` (Matrix identity)
- **Media storage:** `synapse-s3-storage-provider` in local+S3 mode
- **Max upload size:** Configurable via `media_cache.max_upload_size_mb` (default 100 MB). Enforced at both Caddy and Synapse level.
- **Federation:** Disabled
- **Registration:** Disabled for public; admin-only via shared secret
- **Workers:** Single process (monolith). Sufficient for 50-200 users.
- **Element Call:** Configured to use lk-jwt-service for LiveKit token issuance

## Media Storage — Hot Cache with S3 Backend

### Write path

1. Client uploads file to Synapse
2. Synapse writes to local disk
3. `synapse-s3-storage-provider` uploads to Yandex Object Storage asynchronously
4. Local copy remains as hot cache

### Read path

1. Synapse checks local disk cache
2. If present: serve from disk (fast)
3. If absent: fetch from S3, serve to client, local copy is cached

### Cache eviction (`scripts/cleanup-media.sh`)

- Runs on cron (configurable, default daily at 4am)
- Checks current free disk space
- If free space >= `min_free_gb`: no action
- If free space < `min_free_gb`: deletes oldest cached media files (by last access time) until target free space is reached
- Only deletes files confirmed to exist in S3

### Config

```yaml
media_cache:
  max_upload_size_mb: 100
  cleanup_cron: "0 4 * * *"
  min_free_gb: 30
```

## Backup & Restore

### Backup (`scripts/backup.sh`)

- `pg_dump` via `docker compose exec postgres`
- Compress with `gzip`
- Upload to S3 backup bucket via `mc` (MinIO client)
- File naming: `backups/postgres/branga-ru-YYYY-MM-DD-HHMMSS.sql.gz`
- Delete local dump after upload
- Prune remote backups older than `retention_days`

### Automated schedule

Cron job installed on VPS during provisioning. Default: daily at 3am. Configurable via `backup.cron` in `config.yaml`.

### Restore (`scripts/restore.sh`)

```bash
./deploy.sh --restore                    # Lists available backups
./deploy.sh --restore 2026-04-10-030000  # Restores specific backup
```

1. Download dump from S3
2. Stop Synapse
3. Drop and recreate database
4. Restore via `psql`
5. Restart Synapse

## User Management

### Create user

```bash
./deploy.sh --create-user alice
# Output: Created user @alice:branga.ru with password: <auto-generated>

./deploy.sh --create-user alice --password 'MyP@ssword'
```

Implementation:
- SSHes into VPS
- Sources `.env` for `SYNAPSE_REGISTRATION_SHARED_SECRET`
- Performs HMAC nonce exchange with Synapse admin API (`/_synapse/admin/v1/register`)
- Calls registration endpoint via `curl`

## Resource Budget

| Service | RAM (est.) | Notes |
|---|---|---|
| PostgreSQL | 1-1.5 GB | |
| Synapse | 1-2 GB | Monolith mode |
| Caddy | 50 MB | |
| Element Web | 30 MB | Static files |
| LiveKit | 0.5-1 GB | Spiky during calls |
| coturn | 100-200 MB | Spiky during calls |
| lk-jwt-service | 50 MB | |
| OS + Docker | 500 MB | |
| **Total** | **~4-5.5 GB** | ~2.5-4 GB headroom |

Disk: ~15-35 GB used by system + database. 100+ GB available for media cache since primary media storage is S3.

Concurrent video call capacity: 3-5 simultaneous group calls.

## Out of Scope

- Synapse workers (horizontal scaling)
- Email/SMTP notifications
- Open/public registration
- Monitoring (Prometheus/Grafana)
- Federation with other Matrix servers
